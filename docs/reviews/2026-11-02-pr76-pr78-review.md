## Reproduced findings and changes

### Required: Windows checksum test portability

`tests/test_hermes_reviewed_skills.py` built manifest keys with `str(relative_path)`. The committed manifest correctly uses forward slashes, whereas Windows produces backslashes. This is a test-code defect, not corrupted package content and not merely unavailable infrastructure.

The fix uses `relative_path.as_posix()` and explicit UTF-8 reading. A regression exercises Windows-flavoured relative paths on Linux. The original check failed under that simulation; the corrected check passes. Package files, licenses and CHECKSUMS bytes are untouched; file-set, symlink and SHA256 assertions remain enforced.

### Environment: unavailable test PostgreSQL

`tests/test_runs.py::_postgres_available` deliberately raises when `REQUIRE_PG` is set and the test database cannot be reached. Importing `tests.test_atomic_admission` in that state reproduced the reported failure. With PostgreSQL optional, its PostgreSQL class skips while the SQLite concurrency cases pass.

The current main hosted CI has a disposable PostgreSQL 16 service; the Python and separate-worker/restart steps succeeded there. No production database was queried or changed. The original author's precise local traceback was not available, so the reproduced mechanism and current hosted result support the environment classification without inventing their configuration.

### Regression strength: Pydantic state order

The existing runtime already sets `sequential=True`. A new provider-free test delays a `remember` operation while the same model turn also requests `recall`. It verifies both call order and recalled content. An in-memory mutation disabling sequential execution causes the test to fail with `recall, remember`; the actual runtime passes. No runtime implementation or dependency pin changed.

### Follow-up: budget documentation drift

The integration raised the executable total-JavaScript ceiling from 257 to 258 KB. The current build measures about 257.1 KB and passes the new ceiling. This must not be described as passing the previous unchanged limit. First-load JavaScript remains below its unchanged 100 KB ceiling. Older budget prose in `docs/UI_PLAN.md` and historical integration notes is stale; no limit was raised again in this review.
