# Executive workspace hierarchy

Date: 2026-10-24. Status: local acceptance candidate; no production approval.

The owner rejected the rendered local interface and requested a clearer executive
workspace. Keep React, the Dubai font, existing routes, local owner access and all
backend evidence contracts. No animation dependency is added.

Use a restrained dark navigation rail and neutral content surfaces. The next
action becomes a compact, exact-run handoff. Maintenance measures precede the
decision queue in reading order. Decision context, predictive readiness and
secondary recommendations use native disclosures; evidence, assumptions and
human approval are retained. The executive dashboard leads with the server's
headline rather than repeating the product title. Model evaluation tables remain
available behind a disclosure. Unknown periods, owners and targets are not inferred.

Entry motion is a brief transform and opacity transition. System and saved reduced
motion settings still override it. Layouts use logical properties, bounded grids,
wrapping and existing 44-pixel targets. No decorative charts or fabricated trends.

Validation records must distinguish source tests, the local rendered app and any
future hosted acceptance. A local build does not imply a production release.

The final overview places the existing filtered aggregate KPIs and comparison
charts before the detailed maintenance register. Dataset names replace repeated
analysis prompts in dashboard headings. Chart tables,
drilldowns and approval actions retain their existing routes. Recommendation
summaries recognize the backend's conditional scenario claim without relabelling
it as a validated recommendation. Analysis update time is not data freshness.

Actual browser checks covered English desktop, Arabic at 320 pixels, keyboard
chart disclosure and the saved reduced-motion override. These checks do not
constitute a comparison with a rendered Power BI dashboard or physical phone.
A long unbroken dataset filename still needs a narrow-screen wrap adjustment;
the local memory guard deferred that follow-up build.

Follow-up source: scope keyboard focus to the navigation accent on dark sidebar
surfaces, retaining the ordinary accent for controls on the light identity card.
Contrast checks bind the actual CSS outline tokens to both navigation surfaces
and the identity-card background in light, dark and system-dark themes. Long
dataset titles can wrap within their header's available width. These corrections
require a fresh build and actual keyboard/narrow-layout inspection before being
reported as live.

The Phase 1 follow-up supersedes the count-led opening above. Reuse the existing
controlled KPI selection policy for a compact four-card opening, with no new
metric calculations. Move remaining measures into the full register below. Keep
missing readings, undefined values and assessed verdict reasons on each card;
place formula, source, unknown period/owner and freshness context in its evidence
disclosure. Every measure appears once. A real group comparison and the existing
review queue precede the full brief. The period trend and its coverage warning
stay together behind a labelled disclosure. Raw totals imply neither exposure
normalization nor a valid forecast.

If there is no grouping column, the trend is the primary chart and starts open
with its coverage warning. The existing bilingual omitted-period regression
guards this fallback; it must not be weakened to accept an empty opening.
The opening comparison shows the five highest recorded totals, with the actual
displayed count in its bilingual title. The existing Breakdown page retains the
broader comparison and per-record option. This keeps the initial comparison
legible without presenting the subset as the whole population.
Numeric-only uploads use the existing server-backed distribution when neither a
group nor a date is available, with a visible units/targets caution. One concise
period/owner/freshness caution stays above the governed cards; details are not a
substitute for that boundary. Featured percentage meters use the existing accent
token when no family wrapper supplies the family token.
The idle chat-connection Ready strip is visually hidden outside the assistant,
while its accessible status announcement remains. Working, offline, error and
demo states retain their visible feedback. The metadata caution shares the
limitations disclosure summary, avoiding a second warning paragraph.

The source filename and selected record count share a secondary provenance line.
Dashboard pages and filters use contextual disclosures. The sidebar has Decision,
Data & analysis, and Reports & outputs, plus a secondary Workspace tools
disclosure; every old route remains reachable. Native disclosure changes do not
write the hash. The mobile bar opens the three primary work areas and More.
The existing route parser, browser history, mounted view preservation, security
