# Jarvis OS: selected evidence to a reviewed decision

Status: local implementation for owner-requested hackathon review; hosted activation remains gated.

Jarvis OS names a workspace inside Miyaar, not a third-party autonomous operating system or a claim of live model inference. Reuse DataChat, its bounded bilingual grammar, KPI register, source fingerprints, ownership checks and explicit report selection. A separate POST data-query route is read-only and requires read permission, session ownership and the current selection revision. It never falls through to a model or a personal-memory tool. Unsupported questions abstain. No database schema is added by this feature.

Selection is still saved by the existing write-permission API and shown only after confirmation. The query supplies the full selected scope (run, dataset, source hash, analysis revision and filters); the server compares every field under the selection lock. A revision alone was reproduced accepting a different filter selection from another tab, so stale scopes now return 409 before calculation. Changing the selection, question or language invalidates results, cancels the client request and resets local review. Session locks and source checks protect the server; cancellation can leave a bounded read finishing but cannot publish or mutate a report. Review confirmation is explicitly tab-local and is not report approval, publication, dispatch or durable audit evidence.

The opt-in synthetic launcher creates a NEW directory and SQLite database, computes fixture analyses through the real engine and binds only loopback. It refuses an existing destination. Only this launcher exposes the synthetic marker required by the demo entrance. Hosted configuration and provider settings are excluded in this child process. Original user files and databases are never opened. The ordinary application offers Jarvis from Miyaar's conversation toolbar for existing authorized reports.

The expanded owner request brings Jarvis into the actual dashboard. An explicit Connect action creates/reuses a dedicated session and binds the same run and exact chart filters; it does not silently adopt the newest analysis. The bilingual source bar and responsive evidence/assistant columns retain the existing KPI, chart tables, click-to-filter, saved views, six dashboard pages and human approval routes. Changing run, filters or language unmounts the old answer and requires a fresh explicit binding; late responses cannot restore it. The embedded workspace locks report selection to the dashboard and does not label recorded analyses as live telemetry. Read-only mode explains the permission boundary, and connection failures leave analytics available. No new model capability, KPI definition or schema is introduced.

Voice uses the reviewed browser push-to-talk component with its explicit provider disclosure, consent, editable transcript, denial and text fallback. Audio controls default muted. Interrupt/mute unmounts capture and playback. Read-aloud has no automatic fallback to a remote voice: a matching device voice with localService=true is required. Speech has a separate summary retaining units, declared or unknown currency, selected and measured record coverage, and missing-data reasons; displayed evidence, URLs, emails, hashes and IDs are retained literally. Physical microphone and Arabic pronunciation need device acceptance.

Initial JavaScript/CSS budgets remain unchanged. The earlier standalone revision failed CI at 100,042 first-load JavaScript bytes against the 100 KB ceiling. Both concurrent fixes moved request transport out of the initial shell; this integration retains the separate lazy transport module and the incoming shorter bilingual strings. Lazy Jarvis views and bilingual strings justify a bounded total allocation from 258 to 265 KB JavaScript and 35 to 35.7 KB CSS. These total-only allocations include the synthetic entrance and the subsequently requested dashboard-to-Jarvis workspace. The dashboard binding and bilingual controls add about 1.6 KB. No dependency is added. The installed toolchain may differ from lockfile versions; record local evidence separately from hosted reproducible CI.

Tests cover synthetic arithmetic, missing measurements, unsupported predictions, permissions, stale sources, repeated requests, cancellation, UI reset, English/Arabic RTL, phone overflow and mocked denied microphone access. See README for executed evidence. None validates actual LLM inference, engineering safety, operational savings, production identity or database recovery.
