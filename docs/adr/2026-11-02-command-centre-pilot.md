# Command Centre redesign pilot: one primary action, answer first

Date: 2026-11-02 · Status: Accepted. On 2 November 2026 the owner approved
the "calm command centre" direction from a clickable mockup and asked for a
pilot on the first screen.

## Context

The owner compared the interface with reference designs and asked for a
smarter, higher-quality screen. The Command Centre had three problems:

- It stacked three full-width banners.
- It offered two buttons for the same review: "Review" in the brief and
  "Review this report" in the next-step card.
- It showed the KPI values as plain text with a thin rule beside each.

## Decision

1. **One primary action.** When a report waits for approval, the brief has
   no button of its own. The next-step card beside it carries the single
   review action, which opens the analysis that has waited longest. When
   nothing waits, the brief keeps its start button.
2. **The brief and the next step share a row** at 1,100 px and wider, and
   stack below that width. The first screen shows the answer sooner.
3. **The latest analysis's headline is larger and bolder**, so the
   recommendation reads first.
4. **KPI values sit in tiles** with a border, a radius and a raised surface,
   in a larger and bolder figure.

The data, the evidence links, the strings, and the English and Arabic
right-to-left layouts are all unchanged.

## Consequences

- The size budget did not change: CSS total 36,071 of 36,500 bytes, script
  total 271,114 of 272,000 bytes.
- The remaining screens (dashboard and Jarvis, assets, runs) follow the same
  rules in later slices: one primary action, evidence behind a link, and
  Jarvis as an orb with a side panel.

## Verification

- `OverviewStates.test.tsx` checks that the brief has no button while a
  report waits, and that the next-step card's single action opens the
  analysis that has waited longest.
- Before and after screenshots were compared on desktop and phone, in
  English, Arabic, light and dark.

## Follow-up in the same slice: Jarvis evidence text (2026-11-02)

The Jarvis panel set `overflow-wrap: anywhere` on its whole area. That also
lowers the minimum width of every table cell, so narrow evidence columns split
words mid-letter ("Mainten / ance cost"). The rule is now `break-word`: only a
word longer than its line, such as a SHA-256 hash, breaks, and the measures
table scrolls sideways inside its own box. The Jarvis suite
(`playwright.jarvis.config.ts`) passes 10 of 10. The Jarvis screenshots were
regenerated by that suite.
