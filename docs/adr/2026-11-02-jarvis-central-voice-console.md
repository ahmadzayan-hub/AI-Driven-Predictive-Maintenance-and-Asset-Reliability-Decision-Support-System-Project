# Central voice console for the selected analysis

The owner explicitly requested an interactive voice presence after reviewing the static dashboard banner. Preserve the existing deterministic calculations, scope authorization, six dashboard pages and saved views. Place an original cyan radial SVG core between the editable question and evidence, immediately below the overview's four existing governed KPI cards. Other dashboard pages retain their chart/table interactions below the same console. The compact report bar always names its run and dataset. Connection remains explicit and changing filters invalidates both evidence and review.

The core reports actual events: microphone requested, recognition started, transcript preparation, query pending, speech queued, speech started, and unavailable/error. It never infers microphone activity from a button click. Browser recognition provides no audio samples, so the rings are explicitly labelled a state animation, not an amplitude waveform. No second microphone capture, realtime platform, dependency, audio forwarding route or model activation is added. Motion stops when idle and respects both operating-system reduced motion and a local reduce-motion control.

Starting capture interrupts current speech. Stop, mute, changing input/scope/language and unmount dispose capture/playback; late events cannot submit text or restore an answer. The user reviews the transcript and explicitly submits the query. Recognition retains provider disclosure and consent; device playback requires a local voice matching the selected locale and reports unavailable Arabic voice without another-language fallback. Raw evidence, URLs, emails and IDs remain intact; the separate speech summary keeps units, currency uncertainty and coverage. Unsupported analytics still abstain, with no general LLM claim.
