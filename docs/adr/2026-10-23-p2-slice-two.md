# P2 slice two: the store as publish target, logged failures, one error envelope, a required allowlist, recorded migrations, a loud optional-runtime job

Date: 2026-10-23 · Status: Accepted (assessment findings B9, B12, B13, B14,
B16 and G11 in `docs/audits/SAAS_PLATFORM_ASSESSMENT.md`; the second slice
of section 3 of `docs/implementation/DELIVERY_ROADMAP.md`, taken under the
owner's standing instruction to continue slice by slice).

## Decisions

1. **The database store is the publish target (B13).** On approval the
   report and the run log are written to `vault_notes` first, inside the
   approval's transaction, so a host with a read-only filesystem publishes
   completely or not at all. The vault folder is then written as a courtesy
   for Obsidian; when it cannot be (any `OSError`), the artifact's published
   path reads `store:Reports/<note>` and the publish task says the folder
   was not writable. `/api/vault` serves both notes either way. On Vercel the
   model gateway's timeout is clamped to 12 s whatever
   `AGENTIC_OS_MODEL_TIMEOUT_SECONDS` says, because the function has 30 s and
   a call may time out twice.
2. **Failures are logged with the request id, and an outage is a 503
   (B9).** The unexpected-error handler logs the exception type, path and
   request id (with the traceback in the server log, never in the response)
   and answers 503 `database_unavailable` when the error came from the
   database driver, 500 `server_error` otherwise. The memory backend reads
   an empty memory only on a database error, which it logs; any other error
   surfaces as the bug it is. The migration pass asks the catalogue
   (`PRAGMA table_info` on SQLite, `information_schema.columns` on
   PostgreSQL) before each `ADD COLUMN`, so it is repeatable without an
   expected error reaching the database log, and the CI service's health
   check names its database for the same reason. The Python step keeps
   its output and a summary step prints the failures at the end of the
   job, where the service container's log no longer buries them.
3. **One error envelope and the contract behind sign-in (B14, the rest).**
   Every error response carries `detail` exactly as before, so existing
   clients keep working, and `error: {code, message}`: `http_<status>` for a
   plain detail, the operation's own code when it gave one,
   `request_invalid` for a body the schema refused, `database_unavailable`
   and `server_error` for the two above. `GET /api/openapi.json` returns the
   OpenAPI contract to a signed-in reader; the public `/openapi.json` and
   `/docs` stay off. With the idempotency key of slice one, B14 is closed.
4. **The connector allowlist is required in production (B16).** When the
   install is production (`AGENTIC_OS_ENV=production`, a sign-in provider
   configured, or a Vercel deployment) and `AGENTIC_OS_CONNECTOR_HOSTS` is
   unset, every live source is refused with the reason, in both languages.
   Local mode stays open, and the fixture host used by tests and the demo is
   exempt because it never reaches the network.
5. **Migrations are recorded and locked (B12).** A `schema_migrations` table
   records the pass; a database at `SCHEMA_VERSION` skips the `ALTER TABLE`
   pass on every later start, which also ends the "already exists" noise in
   the PostgreSQL log. On PostgreSQL the whole schema pass runs under an
   advisory lock, so two cold-starting instances cannot race on the same
   DDL. Bumping `SCHEMA_VERSION` is how a future step gets its pass.
   A version marker may only skip work it proves done, so the base
   `CREATE TABLE` statements now carry every column the pass adds: a
   fresh database is complete without the pass, and the pass serves only
   databases created before a column existed. The Supabase schema
   snapshot mirrors the base statements in full, with the version table
   under row-level security like every other, and backups carry it.
6. **The optional runtimes are tested, not skipped (G11).** A second CI job
   installs `requirements-agents.txt` (LangGraph, Pydantic AI, the MCP SDK,
   pinned by version) and runs their tests with `REQUIRE_OPTIONAL_RUNTIMES=1`,
   under which a missing runtime fails the module instead of skipping.
   LLMRouter is not in that file and keeps its skip.

## Tests

`tests/test_p2_slice_two.py` (13): publish to the store with an unwritable
vault and with a writable one, the Vercel clamp, the narrow memory except,
the envelope on 404 and 422, the 503 with its logged request id, the
contract behind sign-in, the production allowlist, the recorded schema
version with the skipped second pass, and the optional-runtime guard. The
unknown-path test in `tests/test_api.py` asserts the envelope.
