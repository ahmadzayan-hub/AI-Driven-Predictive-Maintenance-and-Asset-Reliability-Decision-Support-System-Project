# Reference workspace layout

The owner requested a visible redesign using supplied workspace references. The
parent reviewed the latest reference pixels and supplied the observed navy header,
grouped navigation, light canvas, action cards and contextual right panel. This
candidate uses that visual audit; it does not claim local image inspection or a
Stitch-generated implementation.

The shared shell uses a navy header, readable command search, light grouped
navigation and a cool neutral canvas. Existing Dubai typography, semantic status
colors, routes, permissions and source-backed dashboard metrics remain intact.
The assistant places its existing owner-scoped report selector and actual model
availability notice together beside the conversation. On narrow screens the same
controls precede the conversation; no duplicate selector or hidden phone feature
is introduced. Repetitive generic session/mode/governance cards are removed; the
human-review boundary stays beside the source controls.

No reference figures, fake forecasts, online-agent indicators, new backend
capabilities or industrial commands are introduced. Existing artwork is decorative
and encodes no measurement. No model call, external image/font request or new
dependency is required. Dark mode, RTL, keyboard navigation and touch targets remain
acceptance requirements. Synthetic render screenshots establish layout only; local
runtime verification and data preservation are separate release gates.
