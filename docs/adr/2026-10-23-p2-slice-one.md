# P2 slice one: verdict bounds, declared splits, incomplete periods, loopback by default, idempotent run creation, wall-clock limits

Date: 2026-10-23 · Status: Accepted (assessment findings A9, A10, A12, B8,
B14, G10 in `docs/audits/SAAS_PLATFORM_ASSESSMENT.md`; the first slice of
section 3 of `docs/implementation/DELIVERY_ROADMAP.md`, taken under the
owner's standing instruction to continue slice by slice).

## Decisions

1. **A "useful" maintenance-risk verdict needs its lower confidence bound
   above chance (A9).** Balanced accuracy on fifty held-out records swings
   by several points on noise alone, and the earlier rule (five points over
   the baseline and five over chance) called a signal-free target useful
   about one time in fourteen. The stage now also computes the mean, over
   the two classes, of the one-sided 95% Wilson lower bound on each class's
   hit rate, records it on the card and as a calculation the claim cites,
   and requires it above 0.5. The weak verdict names the bound in both
   languages. Twelve seeded noise panels yield no useful verdict.
2. **The split is never silently random (A10).** The train and test split
   records why it is not chronological: fewer periods than five, no date
   column, or a chronological split that left one side too thin. Model
   cards print the reason. A maintenance-risk target with a date column but
   too few periods is not scored at all: a random split of asset history
   lets the model see the future it is scored on. Without any date column
   the every-fifth split is the only one and the card says so.
3. **A partial last period is left out of the trend (A12).** When the last
   period holds fewer records than three quarters of the busiest earlier
   period (the existing uneven-periods ratio), the forecast and the anomaly
   check leave it out, record its count as a calculation and say so in a
   limitation claim. The forecast then starts at that period, read from the
   complete ones, instead of reading a half-filled month as a fall.
4. **The launcher binds to this computer alone unless told otherwise
   (B8).** `python scripts/serve.py` listens on loopback; `--lan` opens the
   local network and prints the consequence (local mode has no login).
   `--local-only` is kept for existing commands and wins over `--lan`.
5. **Run creation is idempotent under a key (B14).** `POST /api/runs`
   accepts an `Idempotency-Key` header (or `idempotency_key` in the body;
   the header wins). The same owner and key return the run already made,
   marked `idempotent_replay`, as a 200 rather than a 201; a unique index
   on owner and key makes this hold across processes. Keys are 1 to 200
   characters. The rest of B14 (one error envelope, OpenAPI behind auth)
   is still open.
6. **Custom stages and agent runtimes have a wall-clock limit (G10).** A
   custom stage runs under `AGENTIC_OS_STAGE_TIMEOUT` (seconds, default
   120) and an agent runtime under `AGENTIC_OS_RUNTIME_TIMEOUT` (default
   60). Python cannot stop a thread, so a call that overruns is abandoned
   on its thread and its result discarded: the stage's task fails with the
   time stated (the run fails only if the stage declared `can_fail_run`),
   and the assistant answers by the rules and says why. This keeps a hung
   stage from hanging a run; it is not a sandbox, and the stages record
   says so.
